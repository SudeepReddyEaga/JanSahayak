Problem Statement & Motivation
The Citizen Welfare Access Dilemma in India
Real-World Societal Challenge

Linguistic Divide: India has 22+ official languages, yet government gazettes and welfare portals are predominantly authored in formal English or bureaucratic Hindi, excluding millions of non-English literate citizens.

Fragmented Bureaucratic Silos: Schemes are dispersed across unlinked ministries (Agriculture, Rural Dev, Health, MSME, Social Justice). Citizens must navigate dozens of portals with no unified point of intake.

Complex Multi-Conditional Rules: Determining eligibility requires evaluating statutory criteria: income caps, land acreage, pucca housing status, BPL cards, caste categories, age boundaries, and gender rules.

Document Ambiguity: Citizens lack clarity on required papers, causing repeated rejections at Common Service Centres (CSCs).

The JanSahayak Multi-Agent Solution

6 Specialized Agents in Sequential Chain: Orchestrated via Microsoft Agent Framework SequentialBuilder, guaranteeing deterministic progression from intake to verified guide.

12 Indian Languages & Voice Accessibility: Full text and STT/TTS voice support for Hindi, Punjabi, Telugu, Tamil, Bengali, Marathi, Kannada, Gujarati, Malayalam, Odia, Urdu (RTL), and English.

Zero-Hallucination GroundingGate: Verifies that every recommended scheme is grounded in official RAG chunks and satisfies mathematical eligibility rules.

Two-Tier Fast & Accurate Redis Cache: Sub-5ms response times via profile-guarded exact and semantic vector cache buckets with zero cross-demographic contamination.

Multi-Agent Coordination
Microsoft Agent Framework Sequential Orchestration
Why Sequential Pipeline Topology?

Ordered Administrative Workflow: Real-world welfare evaluation is inherently sequential: Language/Demographics → RAG Document Retrieval → Rule Verification → Document Checklist → Grounding Check → Language Consistency.

No Race Conditions: Blackboard / Broadcast patterns introduce unpredictable execution order and state conflicts. Sequential ordering eliminates concurrency bugs.

Zero LLM Token Waste: Supervisor agents burn high token budgets re-routing tasks dynamically. A deterministic linear chain provides minimal latency and optimal efficiency.

Rigorous Quality Gates: Permits embedding an explicit GroundingGate between rule evaluation and citizen response.

Framework Primitives & Shared Memory

SequentialBuilder: Chains all 6 agents implementing Microsoft Agent Framework's SupportsAgentRun protocol.

Template Method Pattern: SpecializedPipelineAgent(BaseAgent) handles timing telemetry, session lifecycle, and memory read/write audit logging.

SharedProfileMemoryContextProvider: Reactive context provider that reads and writes UserProfileMemory across the pipeline, syncing with PostgreSQL and Redis.

Audit Ledger: Every agent logs accessed memory fields, duration in milliseconds, and output summaries.

Specialized Agent 2 / 6
Scheme Retrieval Agent (Hybrid BM25 + Vector RAG)
Hybrid Retrieval Architecture

Why Hybrid RAG? Pure sparse search misses semantic meaning in colloquial dialects; pure dense models hallucinate or confuse official scheme acronyms (PM-KISAN vs PMFBY).

Dual-Tier Hybrid Formula:
Score = 0.5 × BM25Score + 0.5 × CosineSim(E_chunk, E_query)

Okapi BM25 Sparse Search: Indexes exact ministry names, portals, and statutory acronyms.

Dense Character 3-Gram Vector Model: Captures sub-word morphology and Indic transliterations invariant to dialectal spelling variations.

Candidate Filtering & Grounding Evidence

Profile-Guided Query Expansion: Ingests the raw query and enriches it with demographic slots (e.g. "elderly rural farmer 2 acres bpl agriculture crop insurance").

Top-K Candidate Selection (K = 10): Retrieves top 10 relevant policy chunks across the 17 seeded welfare schemes.

Chunk Citation Preservation: Associates every candidate scheme with explicit chunk IDs (e.g., PM-KISAN::chunk_0). Mandatory for GroundingGate verification.

Memory Contract: Writes retrieved_chunks and retrieved_scheme_ids to UserProfileMemory.

Specialized Agent 3 / 6
Eligibility Rule Agent (Deterministic Strategy Engine)
Strategy Pattern Comparator Engine

Strategy Table (_OPERATOR_STRATEGIES): Pure, stateless comparison functions for all RuleOperator enums:
LTE, GTE, EQ, NEQ, IN, NOT_IN, BOOL_IS, RANGE.

Strictly Bounded to RAG Candidates: Evaluates only candidate schemes retrieved by RAG, preventing hallucination of arbitrary non-existent schemes.

Composite Rule Grammar:
• all_of (Mandatory Conjunction): Every condition must strictly evaluate to True.
• any_of_groups (Alternative Disjunction): Evaluates alternative branches (e.g. BPL card OR kutcha house).

Tri-State Logic & Audit Trail

Tri-State Classification:
1. ELIGIBLE: Passed all mandatory rules with zero failures and zero missing facts.
2. POTENTIAL: Passed rules, zero failures, pending confirmation of 1-2 missing facts.
3. INELIGIBLE: Failed ≥ 1 statutory rule (e.g. income limit exceeded, govt employee exclusion).

Detailed Rule Audit Trail: Logs exact actual vs threshold values (e.g., "Passed: land_acres=2.0 ≤ 5.0, income=90000 ≤ 200000").

Memory Contract: Writes eligibility_results, eligible_scheme_ids, potential_scheme_ids.

Cross-Scheme Merging & Deduplication

The Multi-Scheme Document Problem: When a citizen qualifies for multiple schemes (e.g., PM-KISAN, PMFBY, PMAY-G, AB-PMJAY), naive systems output 4 duplicate "Aadhaar Card" and "Bank Passbook" bullet points.

Intelligent Merging Algorithm: Uses a keyed hash map merged_docs: dict[str, DocumentRequirement]. When a paper is cited multiple times, it consolidates it into one entry while appending scheme IDs to required_for_schemes.

Localized Document Names: Resolves document titles into the citizen's target language (e.g., 'ಆಧಾರ್ ಕಾರ್ಡ್', 'భూమి పట్టాదారు పాస్ పుస్తకం').

Specialized Agent 5 / 6
Guide Manager Agent & GroundingGate Verification
The Three GroundingGate Invariants

Executed by GroundingGate.verify():

1. Invariant 1 (RAG Retrieval Lineage): Scheme must be present in retrieved_scheme_ids and possess non-empty chunk evidence IDs.

2. Invariant 2 (Deterministic Rule Passage): Scheme must have 0 failed rules and ≥ 1 explicitly passed rule.

3. Invariant 3 (Document Traceability): Every checklist document must link to at least one verified eligible scheme.

Hallucination Blocking: Any ungrounded scheme is stripped from verified_scheme_ids and flagged in ungrounded_claims.

Direct Official Portals for Matched & Non-Matched Policies

Official Portals for Every Evaluated Policy:
• Eligible Schemes (Matched): Official scheme title verbatim, benefit summary, qualification reasons, step-by-step workflow, and direct official portal link (.gov.in / .nic.in).
• Potential Schemes (Pending Facts): Lists missing criteria + direct portal link to confirm requirements.
• Non-Matched Schemes (Other Evaluated Policies): Transparent explanation of why the profile didn't qualify AND a direct official government portal link so the citizen can learn more directly from the ministry.

Transparent Citizen Empowerment: Citizens never reach a dead end. Even when disqualified by deterministic rules, direct links allow exploring policy guidelines, future amendments, and official contacts.

Memory Contract: Writes grounding_report and draft_guide_text.

Language Reviewer Agent (Quality Assurance & Auto-Repair)
Two Mandatory Quality Invariants

Invariant 1: Target Language Script Consistency:
Computes script match ratio: R_script = Target_Chars / Total_Alpha_Chars.
- For Indic languages: Enforces R_script ≥ 0.35 and verifies localized headings.
- For English: Enforces R_script ≥ 0.60.

Invariant 2: Verbatim Scheme Name Preservation:
Official scheme names (e.g., "Pradhan Mantri Kisan Samman Nidhi", "Ayushman Bharat PM-JAY") are statutory legal titles. If translated into arbitrary dictionary words, citizens cannot locate the scheme at physical CSC kiosks. The agent verifies every official name appears verbatim intact.

Deterministic Auto-Repair & Telemetry

Deterministic Auto-Repair Engine: If any official scheme title is altered or omitted, the reviewer automatically restores the canonical scheme title in a formatted block and marks repaired = True. Also restores missing localized greetings.

LanguageReviewReport Telemetry: Records target language, detected reply language, script match ratio, intact names list, missing names list, repairs applied, and diagnostic notes.

Final Memory Write: Commits final_reply_text and language_review_report to UserProfileMemory.

Data & Caching Architecture
PostgreSQL 16 Schema & Two-Tier Redis Cache
PostgreSQL 16 Relational + JSONB Schema

3NF Relational Tables:
• SCHEMES: Primary metadata, official portals, helplines.
• SCHEME_CHUNKS: 1:N pre-embedded RAG policy chunks.
• CITIZEN_SESSIONS: Normalized profiles & memory snapshots.
• AGENT_AUDIT_LOGS: Granular read/write audit entries.
• EVALUATION_RUNS: Historical benchmark records.

JSONB Dynamic Columns: Stores flexible eligibility rules, required papers, and 12-language localized summaries without schema alterations.

Repository Pattern: Decouples storage logic with automatic SQLite local fallback.

Two-Tier Accurate Redis Caching Engine

The Demographic Collision Hazard: Naive semantic caching risks serving a rural farmer's welfare response to an urban college student who asked a similar question.

Canonical Profile Signature Guard: Computes SHA-256 profile_hash over normalized demographic facts before cache lookup, strictly partitioning cache buckets by demographic profile.

Two Cache Tiers:
• Tier 1 (Exact Hit): O(1) lookup on <profile_hash>:<query_hash> (<5ms latency).
• Tier 2 (Semantic Paraphrase): Cosine similarity ≥ 0.90 within the same demographic profile bucket.
• Tier 3: RAG chunk cache and session memory write-through.

Low-Level Design (LLD)
Software Engineering Rigor: SOLID Principles & Design Patterns
SOLID Principles Implementation

Single Responsibility (SRP): Every agent isolates one task (e.g. ProfileIntakeAgent only extracts demographics; DocumentChecklistAgent only deduplicates papers).

Open / Closed (OCP): New rule operators added to _OPERATOR_STRATEGIES and new languages added to language_packs.py without modifying core evaluators.

Liskov Substitution (LSP): RedisCacheStore and InMemoryCacheStore identically fulfill ICacheStore; HTTP and Local memory clients are interchangeable.

Interface Segregation & Dependency Inversion (ISP/DIP): Focused contracts in shared/interfaces/. Pipeline depends strictly on abstract interfaces injected at runtime.

GoF Design Patterns Applied

Template Method Pattern: SpecializedPipelineAgent manages timing, MAF context hooks, and audit logging while subclasses implement domain execute_step().

Strategy Pattern: Used for eligibility rule operator dispatch (_OPERATOR_STRATEGIES) and LLM backend selection (ChatClientFactory).

Repository & Unit of Work Pattern: Decouples data access from business logic via SqlProfileMemoryRepository and SqlSchemeRepository.

Cache-Aside & Decorator Pattern: SemanticQueryCacheService intercepts pipeline requests, checks exact/semantic tiers, and transparently caches outputs.
